# 示例：一堂 60 分钟现场技术分享（非固定模板）

假设用户提供一份《事件驱动自动化基础》讲义，希望做现场培训。

## 不推荐的制作方式

逐节摘录所有术语定义，把“事件源、队列、消费者、重试、幂等、死信”等内容做成 8 条 bullet，字号越压越小；为了节省页数，把所有技术内容压在 4 张幻灯片。

## 推荐的 Storyboard 思路

| 页 | 类型 | 屏幕仅保留 | 详细内容放在 |
|---|---|---|---|
| 01 | 独立封面 | 让系统在事件发生时开始工作 | ImageGen 场景 + Notes |
| 02 | 章节 | 01 为什么需要事件驱动 | 讲师过渡 |
| 03 | 对比 | 人反复查询 vs 事件主动触发 | 图 + Notes |
| 04 | 架构 | 事件源 → 传输 → 执行者 | 原生图 + Notes |
| 05 | 概念 | 事件是工作开始的信号 | ImageGen 概念图 + Notes |
| 06 | 章节 | 02 可靠执行 | 讲师过渡 |
| 07 | 流程 | 失败 → 检查状态 → 安全重试 | 原生图 + Notes |
| 08 | 对比 | 消息重投 ≠ 业务重复执行 | 极简对比 + Notes |
| 09 | 实例 | 一次订单事件如何触发后续工作 | 原生流程 + Demo |
| 10 | 总结 | 触发 / 状态 / 恢复 | 简单框架 |
| 11 | 独立封底 | Build reliable automation. | ImageGen 插画 |

该例只是说明“相同知识量可以由更少文字、更好图形和讲师备注承载”，并不是要求所有课件采用 11 页或必须选择此主题。
