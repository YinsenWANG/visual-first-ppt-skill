## 15 分钟案例的演示契约

使用无真实业务副作用的示例服务：提交一项登记任务，服务生成记录并保存业务主键。

1. 3 分钟：给出输入、业务主键与“最终只有一条有效记录”的验收条件。
2. 3 分钟：正常提交，查看任务状态、服务结果与关联日志。
3. 3 分钟：模拟服务已完成但响应丢失，要求学员判断能否直接重试。
4. 3 分钟：查询外部状态，补写结果并继续；无法确认时进入待核实。
5. 3 分钟：投递重复事件或重启任务，验证业务结果仍唯一。

演示材料须标明现场运行、历史记录或教学推演。没有运行环境时可讨论明确标记的证据样例，不能声称实际部署成功。

## 讲师备注示例：第 9 页

**教学目标**：根据外部业务状态选择恢复动作。

**讲解内容**：超时只表示未收到结果。已执行成功时补写状态并继续；确认未执行且操作可安全重试时有限重试；结果未知或无法查询时保留证据并交人核实。补偿依赖业务规则，不能自动等同于撤销所有操作。

**示例与提问**：展示同一业务主键的提交日志、超时日志和服务记录，请学员指出缺少哪条证据会改变决定。

**常见误区**：把超时都当失败；认为增加一句“不要重复”的 Prompt 就能保证幂等；将任务状态或 Memory 当成外部完成事实。

**时间与过渡**：5 分钟，然后进入重复事件与幂等控制的对比。
